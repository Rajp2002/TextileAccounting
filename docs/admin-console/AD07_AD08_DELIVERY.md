# AD07 and AD08 — read-only money and operating views

Implemented in the isolated `codex/founder-admin` checkout. All examples and database fixtures are synthetic. No production configuration, provider evidence, financial balances or deployed behavior were verified.

AD07 adds `private.admin_billing_facts` and independently recorded `private.admin_billing_coverage`, with service-only founder/session-bound report and audit RPCs. The CLI created `20261004092813_admin_billing_reporting.sql`; it was deliberately reordered to `20261004152000_admin_billing_reporting.sql` after the existing Free and new founder/support/reporting foundations. Ordinary clients and the service client have no direct table grants. An approved importer/backfill is deliberately absent. No gateway call, mutating billing-status endpoint, reconciliation, refund, capture, mark-paid or entitlement change is invoked by a report.

Confirmed amounts require evidenced production classification, live mode, provider event time and verified capture/processed-refund facts. Source amount, organization and provider-identity conflicts are excluded from confirmed/tax totals and block complete net. Original captures survive later refunds; each partial refund has a distinct identity. Integer minor units remain decimal strings in JSON. Independent capture/refund intervals must cover every known provider account without gaps or conflicts before complete net can be shown; unknown/unmapped history also withholds complete totals. A measured empty projection is a zero known subtotal with an explicit incomplete state, never a full zero claim. Unmapped source amounts are labelled all retained history, with no guessed reporting period or mode. Tax-exclusive output identifies only its evidenced subset.

Read limits are 1–100 (default 25) with `(recorded_at,id)` cursors, INR-only half-open periods, maximum 366 days and no future end. Coverage/account outputs refuse populations above 5,000 coverage rows/1,000 account references instead of truncating evidence. The provenance worksheet uses existing ledgers only and makes no writes. Billing readiness exposes existing sanitized state/message and leaves the live document/supplier gate unchanged.

AD08 joins the guarded factory, support, payment and system readers with independent unavailable states. Today provides effective-plan drill-downs and queues ranked by impact, then incident/payment/support need and observed age. Each stable item names the founder owner, reason, target, next action and link. Unobserved activation gaps are unavailable. System reads narrow retained webhook/incident/export failure references and does not interpret an empty register as green health. Workflow latency/volume/success rates, synthetic workflow checks, last backup and last restore test are separate unavailable sources. Audit is bounded, founder-only, immutable to application roles, and includes only allowlisted safe fields.

Changed areas: `lib/admin/{payments-domain,payments,overview,system,audit,report-http}.ts`, reporting APIs under `app/api/admin/{payments,overview,system,audit}`, founder Today/Payments/System/Audit pages, `components/admin/report-ui.tsx`, the additive reporting migration, and named payment/DAL/overview/database tests.
